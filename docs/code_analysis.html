1. 项目全景

一句话：CoTra 把大规模近似最近邻图切分到多台机器，以 RDMA 暴露本地向量内存，并通过“顶层路由 + 分布式图遍历 + 任务下推”减少远程访问和 CPU 通信开销。

在线查询时，每台机器同时承担查询发起者、图计算者和 RDMA 内存提供者的角色。查询被均分到机器，各机器用顶层索引选择候选分片，再协作遍历全局图。

3. 先掌握的核心概念

图 ANNS

每个向量是节点，边连接相近向量。查询维护两个堆：candidate_set 是待扩展候选，top_candidates 是当前最好结果；不断取最近候选并访问邻居，直到其距离不可能改善当前第 ef 名。

分片与副本

part_noreplica_ids[p] 表示真正归属分片 p 的节点；part_replica_ids[p] 还包含为了保持跨分片图质量而复制的节点。构建后需要把副本产生的边收集回节点归属机器。

B1、B2 与 ScalaGraph

名称代码含义访问方式
B1全局/统一编号的 HNSW 风格 level-0 内存布局；由 B1GraphInterface 及其实现加载。可判断节点所在机器和内部编号，远端节点用 RDMA 读。
B2shared-nothing 基线，每机持有独立局部图；查询派发到多个分片后归并。任务/查询消息发送到目标机器执行。
ScalaGraph V3按归属重排全局节点号，本地邻接与远端邻接分开编码，针对 RDMA 粒度优化。微小远端邻接直接读向量；大邻接任务下推至数据所在机。

顶层索引

HNSWTopIndex 从抽样数据构建较小的 HNSW，用作“先找到哪些分片值得搜索”的路由器。它不是最终结果索引；最终精排仍依赖完整分片图和原向量距离。

4. 索引构建完整流程

入口是 tests/scala_index.cc:12。其调用顺序本身就是最可靠的流程骨架：

SharedMem → 解析 RdmaParameter / IndexParameter
          → ScalaBuild::init_rdma()
          → partition()
          → swap_partition_info()
          → build()
          → [SCALA_V3] merge() → transfer_to_scala_v3()
                         → merge_all_b1_index() → build_hnsw_top_index()
          → [SharedNothing] shared_nothing_checkpoint()
                            → trans_to_b2graph() → build_hnsw_top_index()

4.1 初始化与分片

  1. SharedMem 建立线程池、NUMA 内存和线程局部存储环境；构建前线程池暂时 pause。
  2. IndexParameter 读取原始 BIN 文件头获得 vec_num、dim 和元素大小，同时衍生大量临时/最终文件名。
  3. ScalaBuild::init_rdma() 将通信缓冲区注册为 MR，并通过 memcached 交换每线程 QP/MR 元数据。
  4. 0 号机执行 kmeans_partition() 或 random_partition()。输出每分片的 base、idmap、可选 labels，以及 id → partition 映射。
  5. write_partition_info() 生成 label ↔ position 映射，使全局节点按分片连续排列；随后通过 RDMA 把分片元信息分发给成员机。

4.2 局部建图

每台机器在自己的分片上调用 diskann::build_local_partition<T>()。模板类型由 int8 / uint8 / float 和标签类型决定。底层走 DiskANN/Vamana 建图参数 R（最大度）、L（构建搜索宽度）、内存预算和 PQ 配置。

4.3 CoTra 合并路径

  1. partition_checkpoint() 读回本地无副本/含副本 ID 和三个全局映射。
  2. collect_replica_partition() 从本机局部索引中按“节点真实归属”重新组织副本边。
  3. send_replica_partition() 对每个目标机依次发送 meta、ID、邻接数据；目标机轮询并收齐所有来源。
  4. merge_replica_partition() 将远端贡献合并成归属节点的完整邻接表。
  5. transfer_to_b1graph_format() 先形成便于校验/兼容的 B1 格式；transfer_to_scala_v3() 再转成在线访问的紧凑格式。
  6. 0 号机汇总 B1 并从样本构建顶层 HNSW。
为什么有两次“合并”？第一次是把副本机器上生成的边归还给节点所属机器；第二次是布局转换，把算法意义上的邻接表变成适合本地访问和远端 RDMA 的物理格式。

5.2 检索模式

app_type行为适合用来理解
single单机加载 B1 图并做普通 best-first 图搜索。算法基线。
b1分布式全局图，按节点归属进行远端访问/迁移。远程图访问成本。
b2查询派发到 shared-nothing 分片，各自搜索后归并。分片级 scatter/gather。
b2kmeans, b2kmeansbatch用 K-means/顶层索引选择分片，支持批量派发。路由质量与开销。
scala_v3CoTra 主路径：顶层路由、跨机子查询、细粒度任务与异步 RDMA。系统核心贡献。

5.3 Scala V3 的一次查询

  1. 分配：exec_query.h 把 qsize / MACHINE_NUM 个查询分给每台机器，通过 do_all_standby 并行执行并允许窃取任务。
  2. 初始化：scala_search_init() 保存查询基址；scala_search_sub(qid) 创建 QueryMsg，包括向量、ef、候选堆、访问集合和状态。
  3. 预阶段：顶层索引产生入口节点和核心机器集合，建立初始 lowerBound。
  4. 扩展：访问本地邻接；远端微邻接加入异步 RDMA Read 队列，远端大邻接生成 ComputeTask 发送到目标机。
  5. 归并：TaskManager 从接收队列反序列化 task/result/sync，更新全局候选堆、局部任务和计数。
  6. 协作：coro_sub_query_v5() 在等待 CQ 或远端结果时让出执行权，运行时执行其他查询。
  7. 结束：分布式终止成立后产出 QueryMsg::result；发起机与 ground truth 交集计数，计算 recall。

5.4 状态机与终止检测

START → PRE_STAGE → POST_STAGE ⇄ PAUSE → END
          顶层路由      分布式扩展      等消息/无本地工作

QueryMsg 同时保存 post_cnt/recv_cnt、核心/非核心同步计数，以及 has_token、token_is_black、proc_is_black 等字段。这是带颜色令牌的分布式终止思想：只有所有工作和在途消息都被确认，令牌完成一轮且保持白色，查询才可结束，避免“本地队列空”被误判为全局完成。

6. 数据与索引格式

原始向量与查询

uint32_t count
uint32_t dimension
T vectors[count][dimension]     // T = int8_t / uint8_t / float

ground truth 沿用 BIGANN/DiskANN 常见二进制格式，由 AnnsParameter::load_query_gt() 读取并转为每查询优先队列。

ScalaGraph V3 索引文件（每分片）

uint32_t partition_id
uint32_t partition_num
uint32_t local_vec_num
uint32_t local_ngh_ele_size
uint64_t enter_point
uint64_t remote_ngh_num
byte     local_neighbor_area[local_vec_num * local_ngh_ele_size]
uint32_t remote_neighbor_area[remote_ngh_num]

ScalaGraph V3 数据文件（每分片）

uint32_t partition_id
uint32_t partition_num
uint32_t partition_vec_num
uint64_t all_vec_num
byte     entry_vector[vec_size + sizeof(uint64_t)]
byte     vectors[partition_vec_num][vec_size + sizeof(uint64_t)]

节点经过按分片连续重排，因此 cumu_partition_num[p] 既能确定全局 ID 所属机器，也能用 global_id - prefix[p] 得到远端内部 ID。

邻接编码

ScalaGraph 旧/兼容路径将 32 位头拆成：最高位结束标记、12 位分片 ID、低 16 位度数。V3 则进一步固定本地邻接元素宽度，并把较大的远端邻接放进独立区域，通过偏移引用；INLINE_DEG_BAR = 2 的微邻接直接内联。

ABI 注意：文件与网络序列化大量直接 memcpy 原生整数、size_t 和结构字段，没有统一端序/版本号/schema。它默认同架构、同编译配置的集群。

7. RDMA 通信层

对象分工

对象职责
RdmaContext每线程持有 verbs context、PD、CQ、QP、MR、读写计数及远端 rkey/vaddr。
ServerConnect连接 memcached，登记机器，交换 ExchangeMeta，建立路由并提供集群 barrier。
RdmaCommunication面向上层提供 Read/Write/Send、buffer 管理、CQ polling、消息分类与构建同步。
VectorBuffer异步 Read 的本地缓存槽及空闲/完成管理。
SendWriteBuffer / RecvWriteBufferRDMA Write 消息槽，接收侧按 ControlType 分发进不同逻辑队列。

三类操作为何并存

  • RDMA Read：拉取已知地址的远端向量，远端 CPU 不参与，适合小而随机的访问。
  • RDMA Write：推送序列化任务、结果、同步消息和构建期大块数据；控制字告知接收侧如何解释缓冲区。
  • Send/Recv：用于握手或需要接收 WQE 语义的控制路径。

每个工作线程都有独立 RdmaContext（通过 PerThreadStorage），降低锁竞争。poll_send()/poll_recv()/poll_read() 是推进异步状态的核心；上层协程必须持续调用它们，系统没有独立后台 progress thread。

控制平面与数据平面：memcached 只协调机器发现、QP/MR 元数据和 barrier；真正的向量、任务、候选和结果走 RDMA。

8. CoroMem 并行运行时

SharedMem 是进程级 RAII 入口，初始化 ThreadPool、barrier、终止检测和页分配器。线程池根据硬件拓扑记录 socket/NUMA/leader 关系。

抽象用途
PerThreadStorage<T>给每线程一个 T；本线程 O(1) 获取，也能按线程 ID 访问远端槽。RDMA context、Profiler、TaskManager 都用它。
do_all并行遍历固定 range。
do_all_standby做完本地 range 后进入 standby 回调，继续推进网络和服务其他机器查询。
BalanceQueue / worklists线程间负载均衡与 work stealing。
Corobj<T>C++20 coroutine 包装；RDMA 未完成时挂起当前查询，不阻塞 OS 线程。

整体并发模型可概括为：每核一个线程 + 每线程一个 RDMA 端点 + 每线程多个可挂起查询。它用查询级并发覆盖网络延迟，并用 NUMA 本地资源减少共享热点。

10. 构建、参数与运行

依赖与当前构建假设

Linux、GCC/C++20、OpenMP、Boost、libibverbs、librdmacm、libmemcached、Intel oneAPI MKL，另有 DiskANN 子模块。根 CMake 还包含作者机器上的绝对 GCC、RDMA include、MKL/iomp 路径，因此新环境通常不能直接复现。

关键参数

参数含义影响
--graph_typevamana/shared_nothing/Kshared_nothing/scalagraph_v3 等构建布局必须与查询模式匹配。
--app_typesingle/b1/b2/b2kmeans/b2kmeansbatch/scala_v3选择查询执行策略。
-R图最大度越大通常 recall 更高、内存/构建成本更高。
-L构建搜索宽度控制建图质量与耗时。
--res_knn返回 k，默认 10评测结果集大小。
-Q查询数，默认 10000必须不超过 query/GT 文件记录数。
-s数据百万数代码会检查它与文件头向量数一致。
-t线程数当前 MAX_THREAD_NUM=16 还限制元数据数组。

集群启动顺序

  1. 修改配置：首两行为 leader IP/port，随后是 host=machine_id；leader ID 必须为 0。
  2. 所有机器必须使用相同二进制、MACHINE_NUM 和索引路径约定。
  3. 清理/启动 memcached 后，在各机近同时执行同一构建脚本；构建完成后再执行匹配的查询脚本。
  4. 生产复现前先用小数据集，并确认 hugepage、RDMA device、GID/MTU、锁页内存限制。
README 与代码差异：README 示例写 dist_fn=ip，查询解析器实际接受的是 mips；脚本与当前代码也可能来自不同实验版本。以参数解析器为准。

11. 静态分析发现的风险与改进方向

以下是学习和二次开发时优先关注的内容；它们不一定都会在作者的固定实验环境触发。

级别位置/现象影响与建议
高多处 memset(ptr, 0, sizeof(ptr))，例如 scala_build.h 中映射数组初始化。sizeof(ptr) 只有指针宽度，数组绝大部分未初始化。改为已分配字节数或 std::vector(value)。
高ScalaSearch::clear() 无条件释放 data_level0_memory_/linkLists_，而 Scala V3 分支未设置这些 B1 成员；同时图对象也可能拥有同一内存。存在所有权不清、空/重复释放风险。改用明确所有权的 RAII，并按模式销毁。
高ScalaGraphIndex 中 malloc(sizeof(uint32_t) * partition_num + 1)。运算优先级导致只多 1 字节，而代码写到 [partition_num]。应为 sizeof(uint32_t) * (partition_num + 1)。
中get_machine_id() 找不到时无 return；部分错误分支直接 abort()。非法 ID 时为未定义行为；应返回 optional/错误码或抛出含上下文异常。
中通信/文件协议使用裸 memcpy，缺少版本、长度上界、端序和校验。异构节点或配置不一致会静默损坏。增加固定宽度 schema、magic/version/checksum 和边界验证。
中大量裸 malloc/free/new；若构造中途异常，资源回收困难。使用 vector、unique_ptr、MR/QP RAII wrapper，并明确“借用/拥有”。
中CMake 硬编码编译器和作者机器依赖路径，-w 关闭全部警告。妨碍复现且隐藏真实缺陷。使用 find_package/toolchain/cache variables，并开启 -Wall -Wextra。
中MACHINE_NUM、线程数、缓冲区数量均为编译期宏。配置文件机器数必须精确匹配；建议运行期拓扑加上显式容量验证。
低include/index/hnsw/hnsw.h 为空；注释、枚举与 README 中有旧版本名称。增加架构决策记录，删除失效分支或标记实验状态。

测试现状

tests/ 多数是带 main 的实验/诊断程序，并非自动断言式单元测试；根 CMake 没有看到 enable_testing()/add_test() 主线。建议先补纯 CPU 的格式 round-trip、序列化边界、ID 映射、候选堆和终止状态机测试，再做多机 RDMA 集成测试。
